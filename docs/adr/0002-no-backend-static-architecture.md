# ADR-0002：无后端静态架构（桌面优先 + Web 静态构建）

## 状态
✅ 已接受（基线即如此，沿用至今）

## 背景
Chinese-Chess-Max 定位「中国象棋学习/分析助手」：本地屏幕识别 + 本地引擎分析，无账号、无订阅、
无云端计算链路。早期曾有「引入 SaaS 后端」的设想。

## 决策
1. **不引入自建后端服务/数据库**：全部计算在本机（Tauri 2 + Rust + Pikafish + ONNX Runtime）。
2. **Web 发行形态为静态构建**（Vite `dist/`），可托管于任意静态平台/CDN，无服务器逻辑。
3. **拒绝面向该局面的过度工程**：Redis/Kafka/sharding/主从复制均不适用（
   docs/SCALABILITY-REVIEW.md 矩阵逐项论证）。

## 后果
- 优点：零运维、零云成本、隐私好（棋盘画面不离开本机）、构建/发布简单（dist.zip 即产物）。
- 缺点：无云端多端同步、无多人对战托管能力；chessdb.cn 仅作开局库查询（只读、匿名）。

## 未来迁移路径（触发条件才实施）
- 若产品决策加入「多人连线对战」：引入最小服务端（房间调度 + 局面校验），再评估
  WebSocket/消息队列。届时需重新做数据模型与部署架构 ADR。
- 若做「云端对战记录同步」：引入用户体系与存储，属新域，本 ADR 范围外。

## 替代方案（已否决）
- 完整 SaaS 化（高可用/多租户/计费）：与工具定位不符，复杂度与成本不可接受。
