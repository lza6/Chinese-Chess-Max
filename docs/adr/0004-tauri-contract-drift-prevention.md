# ADR-0004：前后端 Tauri 契约防漂移

## 状态
✅ 已接受（2026-09-23 起，持续生效）

## 背景
前端通过 Tauri `invoke(命令)` / `listen(事件)` 与 Rust 后端通信。命令/事件改名或参数变更若
只改一侧，会在运行时静默失效（调用侧报错难排查）。项目规模增长后此类漂移风险显著上升。

## 决策
1. **免手工清单的双向校验**：`scripts/ci/check-contract.mjs` 从 `server/src/lib.rs` 的
   `generate_handler!` 与前端 `invoke("...")`/`listen("...")` 字面量自动提取集合做一致性检查；
   辅以 `tests/Contract.test.ts` 仓库级回归。
2. **兼容泛型调用**：正则支持 `invoke<T>('cmd')` 形式（v0.2.5 修复，防止泛型调用漏检）。
3. **保留命令规则**：后端注册但前端未调用的命令输出 `WARN` 不失败（如 human_move 待产品接线），
   新增前端调用必须同步注册（否则 CI 红）。

## 后果
- 优点：契约漂移在 CI 阶段即暴露；新增命令有强制 checklist 效果。
- 代价：前端使用字符串字面量调用（类型安全由 Tauri 序列化 + 前端接口层承担，可接受）。

## 替代方案（已否决）
- 手写契约文档人工核对：易过期（早期教训：reload_engine 文档与实现脱节）。
- 生成 TS 类型绑定：增加构建复杂度，当前规模收益有限。
